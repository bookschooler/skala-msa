# 서브노트 과제 계획

> 목적: MSA + Agile 방법론을 이해했는지, 조별 프로젝트에서 어떻게 적용했는지 기록

---

## 작성 흐름 (이 순서대로 채울 것)

### 1. 고객 Pain Point & 서비스 제안
- 기존 청약 서비스의 문제점은 무엇인가?
  - 청약홈 / LH청약플러스로 분산돼 있어 통합 조회 불가
  - 인기 단지 접수 시 트래픽 집중 → 장애 발생
- HomeOne이 이를 어떻게 해결하는가?
  - B2B2C 통합 플랫폼: 공급사(B) - 플랫폼(HomeOne) - 청약자(C)
  - MSA 구조로 서비스별 장애 격리

---

### 2. 아키텍처 명세
- 왜 MSA를 선택했는가?
  - 트래픽 급증 구간(청약 접수) 만 독립적으로 확장 가능
  - 한 서비스 장애가 전체 서비스에 영향 없음
- 서비스 구성
  - user-service / course-service / enrollment-service / payment-service / recommend-service
  - 서비스 디스커버리: Eureka
  - 비동기 이벤트: Kafka (결제 완료 → 청약 상태 자동 변경)
  - API Gateway: 단일 진입점, 인증 처리

> ⚠️ 여기서 아키텍처 다이어그램 or 역할_통합분양공고.png 첨부

### 4. API 개발 내용 (내 담당 파트)
- 맡은 역할: course-service (분양 공고 조회/등록)
- 공공 API 연동
  - 청약홈 API → 분양 단지 수집
  - LH API → 공공분양 수집
  - 두 소스를 단일 형태로 정규화 (UnifiedNotice)
- DB 시드 구성
  - 02_seed_suppliers.sql: 공급사 5개 (LH, 경기주택도시공사, 포스코이앤씨 등)
  - 03_seed_courses.sql: 실제 분양 단지 데이터 적재
- 멱등성 보장: 같은 title 중복 INSERT 방지

---

### 5. API 명세서
- Swagger UI 기반 (localhost:8082/swagger-ui.html)
- 주요 엔드포인트
  - `GET /api/courses` — 분양 단지 목록 조회
  - `GET /api/courses/{id}` — 단지 상세 조회
  - `POST /api/courses` — 단지 등록 (공급사 전용)
  - `POST /api/courses/internal/import` — 공공 API 데이터 적재 트리거

> ⚠️ Swagger 화면 캡처 첨부 필요 (내일 Docker 켜서 캡처)
