# 📋 내 작업 정리 — 통합 분양공고 담당 (course-service)

> 실제 코드(`msa-lecture/course-service`)와 실제 API 응답으로 검증한 내용입니다.
> 검증일: 2026-08-26

## 한 줄 요약

> **두 공공기관 API에서 공고를 받아 → 하나의 형태로 정규화해서 → 이미 있는 `courses` 테이블에 넣는다.**
> 조회 API(`GET /api/courses` 등)는 **이미 다 만들어져 있습니다.** 님은 **DB를 채우는 쪽**만 만들면 됩니다.

```
청약홈 API ─┐
            ├─→ [Adapter] ─→ UnifiedNotice ─→ [Importer] ─→ courses 테이블
LH API    ─┘                                                      │
                                                                  ↓
                                        이미 존재 ─→ GET /api/courses (손댈 것 없음)
```

## 🔴 0단계 — 나 혼자 못 하는 선행조건 (지금 당장 확인)

**`courses.instructor_id` 에 `users(id)` 외래키가 걸려 있습니다.**

```sql
FOREIGN KEY (instructor_id) REFERENCES users(id)
```

그리고 `init-db/01_init.sql` 에는 **INSERT 문이 하나도 없습니다** (테이블만 만들고 비어 있음).

> ⚠️ **users 에 공급사 행이 없으면 내 적재 코드는 전부 FK 에러로 실패합니다.**
> 코드를 아무리 잘 짜도 한 건도 안 들어갑니다.

**액션:** ✅ **역할 확정으로 `init-db/` 소유가 나에게 왔습니다. 남에게 요청하지 않고 직접 씁니다.**
`courses` 는 API 적재로 채우므로 시드에 남는 건 **`users` 10줄뿐**입니다.
- `users` 에 공급사 행을 **id 명시해서** INSERT (`INSERT INTO users (id, ...) VALUES (2, ...)`)
- **공급사 id ↔ 이름 목록**을 확정해 `SupplierRegistry` 에 넣고 **PM·추천 담당에게 공유**
- AUTO_INCREMENT 에 맡기면 `down -v` 후 id가 밀려서 공공/민간이 뒤바뀝니다
- ⚠️ **`down -v` 실행 권한은 PM 독점**입니다. 시드를 고쳤으면 PM에게 반영 요청하세요
  (정해진 슬롯: D1 16:35 / D2 09:10 / D2 13:00)

**대응 (컬럼 추가 0개):** A안이면 `title` 이 `검암역 푸르지오 84A` 처럼 유니크해집니다.

### 기존 `POST /api/courses` 는 적재에 못 씁니다

공급사가 여러 곳인 데이터를 넣어야 하는데 헤더로는 한 명만 지정됩니다.
→ **Repository 로 직접 저장하는 Importer** 를 따로 만드는 게 맞습니다.

## 🚧 실데이터 때문에 생기는 결정사항 3개

### ① 지역 — enum 이 3개뿐인데 실데이터는 전국입니다

`Course.Category` 는 `SECURITY`(서울) / `MOBILE`(경기) / `DATABASE`(인천) / `OTHER` 만 씁니다.
2026년 표본 300건 기준 **서울+경기+인천 = 115건 (38%)**, 나머지는 전부 `OTHER` 가 됩니다.

**대응: 수집할 때 지역 필터를 걸어서 3개 지역만 가져옵니다.**
```
cond[SUBSCRPT_AREA_CODE_NM::EQ]=서울   ← 검증 완료, 100/100 정확히 서울만 반환
```
서울/경기/인천 3번 호출해서 합칩니다. `OTHER` 범벅을 피할 수 있습니다.

### ② 몇 건 넣을 것인가

조별플랜 권장은 12~15건. A안이면 **공고 5~6건만 가져와도 주택형 전개로 30~50건**이 나옵니다.
→ 지역별 공고 2건씩 × 3지역 = 6건 → 충분합니다.

### ③ 실제 건설사명이 그대로 들어옵니다

`푸르지오`, `대우건설` 같은 실명이 API 응답에 있습니다.
공공데이터포털 데이터는 이용허락 제한이 없어 **인용 자체는 문제없습니다.**
플랜의 "가상" 규칙은 *우리 서비스가 청약홈인 척하지 말라*는 뜻이므로,
**출처를 밝히면(「한국부동산원 공공데이터 인용」) 실명 그대로 써도 됩니다.**
불편하면 `SupplierRegistry` 에서 가명으로 치환하면 되므로, 이건 나중에 바꿔도 되는 결정입니다.
