## 0. 이 지시서의 전제

**코드 수정은 필요 없습니다.** 승환님이 작성하신 코드는 그대로 정상 동작합니다.
윤소영 로컬에서 **회원가입 → 로그인 → 청약신청 → Kafka 상태변경**까지 전 구간 성공을 확인했습니다.

차이는 **git으로 전파되지 않는 3가지(환경변수 파일, 도커 이미지 빌드, DB 볼륨)** 뿐입니다.
아래 4단계를 순서대로 실행하면 동일한 동작 상태가 됩니다.

## ⚠️ 실행 위치 주의 (자주 나는 실수)

아래 모든 `docker compose` 명령은 **`docker-compose.yml` 이 있는 `msa-lecture/` 안에서** 실행해야 합니다.

```bash
pwd
# → .../msa-lecture   여기면 OK. cd 하지 말고 바로 실행
# → .../<레포 루트>   여기면 cd msa-lecture 먼저
```

- **레포 루트에서 실행하면**: `docker-compose.yml` 을 못 찾아 **조용히 아무 일도 일어나지 않습니다.** (에러도 안 남)
- **이미 `msa-lecture` 안인데 `cd msa-lecture` 를 또 치면**: `no such file or directory` 가 나고,
  `&&` 로 이어붙인 뒤 명령(`docker compose build`)이 **실행되지 않습니다.**

이 지시서의 `cd msa-lecture` 는 **레포 루트 기준**입니다. 이미 안에 계시면 `cd` 를 빼고 실행하세요.

## 2단계. 환경변수 파일 2개 생성 ⚠️ 가장 중요

두 파일 모두 `.gitignore` 대상이라 **git으로 전파되지 않습니다.** 각 로컬에서 직접 만들어야 합니다.

### 2-1. `msa-lecture/.env` (게이트웨이용)

```bash
cd msa-lecture
echo 'OAUTH_CLIENT_SECRET=web-secret' > .env
```

- 없으면 `docker compose up` 시 `OAUTH_CLIENT_SECRET` 미해결로 **게이트웨이가 기동하지 않습니다.**
- 값 `web-secret` 은 auth-server에 등록된 `web-client` 의 시크릿입니다.

### 2-2. `msa-lecture/vue-frontend/.env` (프론트용)

```bash
cat > vue-frontend/.env <<'EOF'
VITE_API_BASE_URL=http://localhost:8080
VITE_AUTH_SERVER_URL=http://localhost:9000
VITE_CLIENT_ID=web-client
VITE_CLIENT_SECRET=web-secret
VITE_REDIRECT_URI=http://localhost:3000/callback
VITE_USE_BACKEND_DATA=true
EOF
```

#### 🔴 핵심 주의 — `VITE_AUTH_SERVER_URL` 은 반드시 `9000`

커밋 `5ecca5f` 에서 `store/auth.js` 의 기본값이 `8080` → `9000` 으로 변경되었습니다.

```js
// 브라우저의 인증 화면은 Auth Server에 직접 연결하고, API 호출만 Gateway를 사용한다.
const AUTH_SERVER_URL = import.meta.env.VITE_AUTH_SERVER_URL || 'http://localhost:9000'
```

**그러나 `.env` 파일 값이 기본값보다 우선합니다.** 기존 `.env` 에 `8080` 이 남아 있으면
코드를 아무리 고쳐도 `8080` 으로 이동하며, 로그인 버튼 클릭 시 **흰 화면**이 뜹니다.
(윤소영 로컬에서 실제로 발생했던 증상이며, 이 값을 `9000` 으로 고쳐 해결했습니다.)

#### 🟠 `.env.example` 보완 필요 (별건)

현재 `vue-frontend/.env.example` 에 **`VITE_CLIENT_SECRET` 항목이 누락**되어 있습니다.
예시 파일만 보고 `.env` 를 만들면 이 값이 빠집니다. 승환님 판단으로 추가 부탁드립니다.

## 4단계. DB 초기화 (분양공고가 79건으로 보이는 경우만)

```bash
docker exec lecturedb mariadb -umanager -pSqlDba-1 lecture_db -e "SELECT COUNT(*) FROM courses;"
```

- **1523** → 4단계 건너뛰고 5단계로
- **79 또는 그 외** → 아래 실행

```bash
cd msa-lecture
docker compose down -v      # ⚠️ -v 필수
docker compose up -d
# 기동 완료까지 3~5분 소요 (auth-server healthy 대기)
```

### 왜 `-v` 가 필요한가

`init-db/*.sql` 은 `/docker-entrypoint-initdb.d` 로 마운트되며, MariaDB는 **데이터 디렉터리가 비어 있을 때만** 이 스크립트를 실행합니다.
`mariadb_data` 는 named volume이라 `docker compose down` 만으로는 삭제되지 않아,
`git pull` 로 `03_seed_courses.sql` 이 1,523건으로 갱신돼도 **DB에는 반영되지 않습니다.**
에러 없이 조용히 옛 데이터가 유지되므로 발견이 어렵습니다.

⚠️ `-v` 는 로컬 DB를 전부 삭제합니다. 테스트로 넣어둔 데이터가 있으면 함께 사라집니다.

## 5단계. 프론트 dev 서버 재시작 ⚠️ 필수

`vite.config.js` 와 `.env` 는 **서버 기동 시점에만 읽힙니다.**
`.vue` 파일과 달리 실행 중 자동 반영되지 않으므로 반드시 껐다 켜야 합니다.

## 6단계. 검증

### 6-1. 인프라 레벨

```bash
# 게이트웨이 공개 API — 200 이어야 함 (이전에는 401)
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/api/courses
# → 200

# 인증 필요 API — 401 이어야 정상 (토큰 없이 호출)
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/api/enrollments/my
# → 401

# 토큰 교환 엔드포인트 — 400 이어야 정상 (빈 body)
curl -s -o /dev/null -w "%{http_code}\n" -X POST \
  -H "Content-Type: application/json" -d '{}' http://localhost:8080/api/auth/token
# → 400  (404면 게이트웨이가 옛 이미지)

# 인증 서버 로그인 페이지
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:9000/login
# → 200

# Eureka 등록 서비스 목록 (7개여야 정상)
curl -s -H "Accept: application/json" http://localhost:8761/eureka/apps \
  | python3 -c "import sys,json;a=json.load(sys.stdin)['applications']['application'];print(len(a),'개:',[x['name'] for x in a])"
```

### 6-2. 백엔드 단독 검증 (프론트 제외)

프론트 문제인지 백엔드 문제인지 가르는 용도입니다.

```bash
curl -X POST http://localhost:8083/api/enrollments \
  -H "Content-Type: application/json" \
  -H "X-User-Id: 1" \
  -d '{"courseId": 162}'
```

**기대**: `201` + `{"success":true,...,"status":"PENDING"}`

⚠️ `courseId` 는 **162 이상**을 사용하세요. 시드 데이터의 `courses.id` 범위는 **162 ~ 3063** 입니다.
(1~10 등을 넣으면 `"존재하지 않는 강의입니다"` 400이 납니다 — 정상 동작입니다.)

### 6-3. 브라우저 E2E (최종 확인)

| 순서 | 동작 | 주소 |
|------|------|------|
| 1 | 회원가입 (비밀번호 **8자 이상**) | `http://localhost:3000/register` |
| 2 | **[공동·금융인증서 로그인]** 클릭 | `http://localhost:3000/login` |
| 3 | auth-server 로그인 화면(`Please sign in`)에서 로그인 | 자동 이동 |
| 4 | 분양 목록 → 단지 선택 → 청약 신청 | `http://localhost:3000/announcements` |
| 5 | 내 청약 내역에서 🟢 접수확정 확인 | `http://localhost:3000/applications` |

> 🔴 **2단계에서 [시연용 계정으로 둘러보기] 를 누르면 안 됩니다.**
> `store/auth.js:34` 의 `loginAsDemo()` 가 `'demo-token'` 을 설정하고,
> `store/application.js:47` 의 `if (auth.accessToken !== 'demo-token')` 조건에 걸려
> **서버 호출을 건너뛰고 localStorage에만 저장**됩니다. DB에 들어가지 않습니다.

### 6-4. DB 확인

```bash
docker exec lecturedb mariadb -umanager -pSqlDba-1 lecture_db -e "
SELECT e.id, u.name AS 신청자, LEFT(c.title,28) AS 단지, e.status, p.status AS 납부
FROM enrollments e
JOIN users u ON u.id=e.user_id
JOIN courses c ON c.id=e.course_id
LEFT JOIN payments p ON p.user_id=e.user_id AND p.course_id=e.course_id
ORDER BY e.id;"
```

**기대**: 신규 행이 `status = ACTIVE`, 납부 `COMPLETED`
