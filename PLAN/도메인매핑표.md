## 0. 프로젝트 주제

> 여러 건설사·시행사의 **공공·민간 분양 정보를 한 곳에 모아**,
> 청약 신청자에게는 **조건에 맞는 분양 단지를 추천**하고,
> 공급사에게는 **접수 현황을 제공**하는 **B2B2C 분양 정보 플랫폼**.
>
> 인기 분양 접수 시점에 트래픽이 몰려도 **조회·추천이 멈추지 않도록** 서비스를 분리했습니다.

- **B (공급사)** = 건설사·시행사 → 분양 공고 등록, 접수 현황 확인
- **C (신청자)** = 개인 → 단지 조회, 맞춤 추천, 청약 접수, 접수 수수료 납부

> ⚠️ **안전 규칙** — 실제 「청약홈」·한국부동산원을 흉내내지 않습니다.
> 서비스명·단지명·건설사명·신청자명은 **전부 가상**입니다. 실존 브랜드(자이·래미안·힐스테이트 등) 사용 금지.
> 실제 개인정보(주민번호·전화번호·주소)는 어떤 필드에도 넣지 않습니다.

## 3. `category` enum 매핑 ⭐ 가장 중요

`Course.Category`는 **코드에 고정된 enum**이라 `SEOUL` 같은 새 값을 쓸 수 없습니다.
**기존 8개 값 중 3개를 지역 코드로 재해석**합니다. (코드 수정 0줄)

| enum 값 (DB·API에 들어가는 값) | 우리 지역 | 화면 표기 |
|---|---|---|
| `SECURITY` | 서울 | **서울** |
| `MOBILE` | 경기 | **경기** |
| `DATABASE` | 인천 | **인천** |
| `OTHER` | 기타 | **기타 지역** (예비) |
| ~~`BACKEND`~~ ~~`FRONTEND`~~ ~~`DEVOPS`~~ ~~`DATA_SCIENCE`~~ | **쓰지 마세요** | 서버가 "백엔드"로 자동 번역해버림 |

> ⚠️ **`BACKEND` / `FRONTEND` / `DEVOPS`는 절대 쓰지 마세요.**
> enrollment-service 내부에 `BACKEND → "백엔드"` 로 바꾸는 코드가 있어서,
> 「내 접수 내역」 화면에 지역 대신 **"백엔드"** 라고 튀어나옵니다.
> 위의 4개(`SECURITY`/`MOBILE`/`DATABASE`/`OTHER`)는 그대로 통과합니다.

## 4. 공공 / 민간 구분 (컬럼 추가 0개)

**`instructor_id`(공급사) 자체가 공공/민간을 결정**합니다. 별도 컬럼을 만들지 않습니다.

| 공급사 ID | 공급사명 (가상) | 구분 |
|---|---|---|
| `2` | 한빛주택공사 | 🏛️ **공공분양** |
| `3` | 새도시개발공사 | 🏛️ **공공분양** |
| `4` | 대성건설 | 🏢 **민간분양** |
| `5` | 유진종합건설 | 🏢 **민간분양** |
| `6` | 하늘건설산업 | 🏢 **민간분양** |

> **왜 컬럼을 안 만드나요?** — 공급사가 곧 공공/민간이므로 별도 컬럼을 두면
> "공공기관인데 민간분양"처럼 **모순된 데이터**가 생길 수 있습니다.
> 정규화 관점에서 컬럼을 안 두는 게 맞습니다. → **발표 포인트**

};

export const ENROLL_STATUS = {
  PENDING:   '접수완료',   // 수수료 납부 대기
  ACTIVE:    '접수확정',

// 분양가는 '만원' 단위로 저장 → 화면에서 억/만원으로 변환
export const formatPrice = (manwon) => {
  const eok = Math.floor(manwon / 10000);
  const man = manwon % 10000;
  return eok > 0
    ? `${eok}억 ${man ? man.toLocaleString() + '만' : ''}원`
    : `${man.toLocaleString()}만원`;
};

## 6. ⚠️ 코드에 박혀 있는 제약 5가지 (반드시 알고 시작)

| # | 제약 | 우리 대응 |
|---|---|---|
| 1 | `category`가 **enum 고정** (새 값 추가 불가) | 3장의 재해석 매핑 사용 |
| 2 | `price`가 `DECIMAL(10,2)` → **최대 약 1억** | **분양가를 "만원" 단위로** 저장 (`68000` = 6.8억) |
| 3 | 수수료가 **99,000원으로 코드에 고정** | 그대로 두고 **"청약 접수 수수료 99,000원 정액"** 이라고 부름 |
| 4 | `enrollment_count`는 **API로 못 넣음** (접수해야 +1) | 데모용 숫자는 B가 **DB에서 직접 UPDATE** (데이터 조작이라 허용) |
| 5 | `CourseResponse`에 **공급사 "이름"이 없음** (`instructorId`만 옴) | 프론트에서 5장의 `SUPPLIER` 표로 변환 |

## 9. AI 추천 로직 (A 담당, 코드 1줄)

`recommend-service/app/service/recommend_service.py` **94번째 줄**

```python
reverse=True    # 원본: 인기 많은 순
        ↓
reverse=False   # 우리: 접수 건수가 적은 순 = 당첨 확률 높은 순
```

**발표 문장:**
> "인기 단지만 보여주면 모두가 같은 곳에 몰립니다.
> 저희는 **접수 경쟁이 덜한 단지를 먼저 추천**해서, 신청자의 **당첨 가능성**을 높였습니다."

- 신규 사용자 → 경쟁 낮은 단지 추천
- 기존 사용자 → 이전에 청약한 **지역**을 분석해 같은 지역 단지 추천 (`_find_dominant_category`)
