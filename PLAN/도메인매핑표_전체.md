# 도메인 매핑표 — 기존 DB 컬럼명 ↔ 우리 프로젝트 의미

> 교수님이 제공한 DB는 온라인 강의 플랫폼 기준으로 설계되어 있습니다.  
> 컬럼명·테이블명 변경 없이 그대로 사용하되, 아래 표와 같이 도메인 의미를 재해석하여 사용합니다.

---

## 테이블명 매핑

| 기존 테이블명 | 우리 프로젝트 의미 | 비고 |
|------------|----------------|------|
| `users` | 사용자 (청약자 / 공급사) | role 값으로 구분 |
| `courses` | 분양 공고 (단지) | 공공 API 데이터 적재 대상 |
| `enrollments` | 청약 신청 | 청약자의 공고 신청 기록 |
| `payments` | 접수 수수료 결제 | 청약 신청 후 수수료 처리 |

## 매핑 원칙

1. **테이블명·컬럼명 변경 금지**: 교수님이 제공한 DDL(`01_init.sql`)을 그대로 사용
2. **enum 재해석**: category enum을 지역 코드로 재사용 (코드 수정 없이 의미만 변경)
3. **role 구분**: STUDENT = 청약자, INSTRUCTOR = 공급사
4. **가격 단위**: price 컬럼은 만원 단위 (48630 → "4억 8,630만원" 변환은 프론트에서 처리)
5. **외래키 유지**: instructor_id → users.id FK 그대로 사용 (공급사가 users 테이블에 INSTRUCTOR로 등록)
